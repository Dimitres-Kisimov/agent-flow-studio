# Flow dependency report

Generated by `node scripts/analyze-flows.js --write` from the flows in the folders below.
It is a pure, deterministic function of those files — re-running reproduces it byte-for-byte,
so it can be committed and diffed. The example flows are illustrative, not exhaustive.

This is a **static** data-dependency analysis over the graph edges and node types alone. It
reports each node's dependencies, the topological run order, the **stages** whose nodes could
run in parallel, the **critical path** (the minimum number of sequential stages), and the
**provenance** of every Output (which Trigger can feed it). Like the linter it treats BOTH
branches of a Condition as reachable — it does not follow the single branch taken at run time,
so these describe *potential* data flow, not the one path a given input takes.

## What each column means

| Field | Meaning |
| --- | --- |
| Nodes / Edges | Node count and raw edge count of the flow. |
| DAG? | Whether the dependency graph is acyclic. A cycle or self-loop makes it `no`. |
| Stages | Number of topological levels. Nodes in one stage have no dependency between them, so they could run in parallel. |
| Depth | Length of the critical path — the minimum number of sequential stages the flow needs. |
| Provenance | For each Output, the Trigger(s) whose payload can reach it (both Condition branches counted). |
